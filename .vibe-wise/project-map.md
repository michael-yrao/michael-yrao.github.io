# Project Map

## Purpose
Progressive Overflow (progressiveoverflow.com): an Angular site that renders step-by-step LeetCode algorithm visualizers, a progress page driven by the learner's cse-progress repo, a practice page, and a Tech Events and interview-directory API served by a Cloudflare Worker. Source: `CLAUDE.md`, `package.json` (name `progressive-overflow`).

## Requirements
Unknown. The files inspected state conventions (visualizer quality bar, contract mirroring), not user needs or constraints beyond those.

## Components
- Algorithm visualizers: one `*.steps.ts` per problem under `src/app/algorithms/<category>/` (categories: arrays-hash, backtracking, binary-search, dynamic-programming, graphs, greedy, heap, linked-list, sliding-window, stack, trees, trie, two-pointers); each exports an `AlgorithmMeta` with `SolutionVariant`s. Spec: `src/app/algorithms/algorithms.steps.spec.ts`.
- Registration: `src/app/core/data/algorithms.data.ts` (hand-edited wiring) and the generated `src/app/core/data/algorithms.index.ts` (header "GENERATED by scripts/gen-registry.mjs — do not edit"), produced by `scripts/gen-registry.mjs`.
- Progress feature: `src/app/features/progress/` (page and today-board per `CLAUDE.md`), fed by `src/app/core/services/progress.service.ts`.
- Showcase and solution code: `src/app/core/services/showcase.service.ts` fetches cse-progress `dashboard/showcase.json`; `src/app/core/services/github-file.service.ts` holds `GOLD_STANDARD_REPO`.
- Practice: `src/app/features/practice/` (practice page, solution page, step visualizer), `src/app/core/services/practice.service.ts`.
- Interview feature: `src/app/features/interview/` (setup, prepare, page, directory, debrief), with `src/app/features/interview/directory/directory-contract.ts` mirrored from the worker.
- Events feature: `src/app/features/events/`, `src/app/core/services/events.service.ts`, model `src/app/core/models/events.model.ts`.
- Algorithms route: `src/app/features/algorithms/algorithms.routes.ts` is redirects only (legacy `/algorithms/:category/:id` -> `/practice/<n>/solution`, query string preserved). The visualizer page is `features/practice/solution-page`.
- Library hub `src/app/features/library/` (link cards + `GroundednessMeter`; `CHEAT_SHEET_COUNT` is a hand-kept literal). Learn `src/app/features/learn/` (18 technique cheat sheets from `cheat-sheet.service.ts`, repo JSON with bundled fallback; decision tree dark-launched behind `LEARN_DECISION_TREE_ENABLED`). Quiz `src/app/features/quiz/` (Pattern Sense over `ALGORITHM_INDEX`; Big-O trainer over `dashboard/big-o.json`). Games `src/app/features/games/` (5 runtime-generated mini-games with pure `*.solver.ts`/`*.rounds.ts` files; plain fields + manual `markForCheck`). Coach `src/app/features/coach/` (static explainer; CTA gated by `COACH_REPO_IS_PUBLIC`). About `src/app/features/about/` (bio + signal-driven SVG barbell lifter).
- Shared `src/app/shared/`: five visualizers dispatched by `state.type` in `features/practice/step-visualizer` (`@switch`, no default); 13 components (page-header, library-subnav, code-viewer, code-editor (CodeMirror), grounded-code-panel, groundedness-meter, step-controls, ...); `_workbench.scss`; utils (shuffle, practice-split, practice-shortcuts, practice-contract).
- Practice runtime: `src/app/core/runner/` runs learner Python in a module Web Worker with Pyodide from jsDelivr (`PYODIDE_INDEX_URL`); verdicts are judged in TS by `core/practice/compare.ts`.
- Data funnel: `src/app/core/services/github-file.service.ts` (manifest sha -> Cache API -> Contents API -> raw on 403); `author-fallback.ts` (viewer repo, gold on 404 only).
- Other services: `src/app/core/services/big-o.service.ts`, `cheat-sheet.service.ts`, `contract-cache.ts`, `contract-manifest.ts`.
- Site links and worker URL: `src/app/core/data/site-links.ts` (`WORKER_API_URL`, `EVENTS_API_URL`, `INTERVIEW_CODES_ENABLED`, `EVENTS_FEED_ENABLED`).
- Worker `po-api`: `worker/` (own toolchain), config `worker/wrangler.toml`, docs `worker/README.md`, source under `worker/src/` (`sources.ts`, `contract.ts`, `normalize.ts`, `interviews/`).

## Main Flow
Verified from `CLAUDE.md` and service/workflow file names; internals of each page not inspected.

```
cse-progress dashboard/showcase.json --(GitHub fetch)--> ShowcaseService --> visualizer/practice pages (anchors resolve code)
cse-progress dashboard/progress-summary.json + progress.json --(GitHub Contents API)--> ProgressService --> Progress page
worker po-api (public event feeds, KV interview records) --(HTTP, CORS)--> EventsService / interview directory --> Events and interview pages
```

## Data and Trust Boundaries
- GitHub Contents API (`Accept: application/vnd.github.raw`, cache max-age 60) for cse-progress files; falls back to raw.githubusercontent.com only on a 403 from the API (`CLAUDE.md`, `src/app/core/services/progress.service.ts`).
- Viewer-supplied `?repo=owner/name[@branch]` is validated by `ProgressService.parseRepo`; default repo is `DEFAULT_REPO`.
- Worker stores interview records in Cloudflare Workers KV (binding `INTERVIEWS` in `worker/wrangler.toml`); rate-limit bindings `INTERVIEW_READS` and `INTERVIEW_WRITES` are declared there.
- Worker polls public tech-event feeds listed in `worker/src/sources.ts`.
- Auth: none found in the files inspected (no auth mechanism named in `CLAUDE.md`, `worker/README.md` or `site-links.ts`); the Cloudflare API token and account id are CI deploy secrets only.
- The learner's solution code is never stored in this repo; fetched at runtime from cse-progress.

## Build and Deployment
- Site: `.github/workflows/deploy.yml`. On push to `main` (and pull_request, workflow_dispatch) it runs `npm ci`, lint, `check:contract-mirror`, `check:registry`, `check:sitemap`, `npx ng test --watch=false`, the groundedness check, `npm run build`, and e2e; the deploy job (not on pull_request) publishes `dist/progressive-overflow` to GitHub Pages. Custom domain via `src/CNAME` listed in `angular.json` assets.
- Worker: `.github/workflows/worker.yml`. On push to `main` touching `worker/**` (plus the workflow file, `src/app/core/models/events.model.ts`, `src/app/features/interview/directory/directory-contract.ts`, `scripts/check-contract-mirror.mjs`) it typechecks, runs the mirror check and tests, then runs `wrangler deploy` via `cloudflare/wrangler-action` only if the Cloudflare secrets are set.
- Daily groundedness re-check: `.github/workflows/groundedness.yml` (contents not inspected beyond `CLAUDE.md`'s description).
- Local scripts from `package.json`: `start`, `build`, `test`, `lint`, `e2e`, `gen:registry`, `gen:sitemap`. Node 24 per `CLAUDE.md`.

## Verified 2026-10-08 (walkthrough sweep)
- Worker routes: `GET` any non-`/interviews/` path -> events feed; `/interviews/c/{id}` GET; `/interviews/i/{id}` GET/PUT/DELETE (`worker/src/interviews/handler.ts`). KV `INTERVIEWS`, 180-day TTL, tombstones on delete, fail-closed rate limits (reads 60/min, writes 6/min).
- `groundedness.yml`: daily cron + `repository_dispatch` + manual; curls live showcase.json and runs `check:groundedness`; publishes nothing.
- `/coach` links `SITE_LINKS.coachRepo` (github.com/michael-yrao/cse-coach); CTA reads "Request access" while `COACH_REPO_IS_PUBLIC` is false.
- Auth: none in the site; the interview directory uses a bearer write token derived from the interviewer code (PBKDF2), stored server-side only as a SHA-256 hash.
